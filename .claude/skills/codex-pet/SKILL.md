# 桌宠生图规范（Codex 桌宠格式）

小组件上的桌宠就是一张 **Codex 桌宠格式**的精灵图（ADR 0044）。这份规范只解决一件事：
**让任何生图模型画出来的图，能稳定地切成这个格式，并且动作、比例、颜色都对得上。**

- 程序的真相源：`moodflow_hub/src/windows/widget/pet.ts`（动作表、何时播放）、`moodflow_hub/src-tauri/src/pets.rs`（导入校验）、
  `moodflow_hub/src/windows/widget/App.vue`（换装锚点）。本规范与它们冲突时**以代码为准**，并回来改这里。
- 机器可读的排版：同目录 `layout.json`（切图工具读它）。逐帧动作说明：`references/actions.md`。提示词：`references/prompts.md`。
- 切图工具：`tools/pet_from_grid.py`。旧的程序画法：`tools/gen_pet_sheet.py`（保留作对照，不再用于出新形象）。

## 一、项目支持的动作（只画这些）

精灵图 8 列，每格 **192 × 208**，9 行，每行一个动作。帧数和一轮时长是 Codex 定死的，**不能多也不能少**：

| 行 | 动作 | 帧数 | 一轮 | Moodflow 什么时候播 | 画什么（详见 actions.md） |
|---|---|---|---|---|---|
| 0 | `idle` | 6 | 1100 ms | 平时（晴、多云、一阵风） | 原地轻轻呼吸，第 5 帧眨眼 |
| 1 | `running-right` | 8 | 1060 ms | 被拖着往右、沿屏幕底边往右散步 | 面朝右的跑步循环 |
| 2 | `running-left` | 8 | 1060 ms | 往左拖、往左散步 | 面朝左；**默认由 running-right 镜像，不用画** |
| 3 | `waving` | 4 | 700 ms | 新的暖心话 / 提醒 / 周信（两轮）、被单击 | 举手打招呼，笑眼 |
| 4 | `jumping` | 5 | 840 ms | 打错字（吓一跳）、扔出去落地 | 下蹲 → 起跳 → 最高点 → 下落 → 落地 |
| 5 | `failed` | 8 | 1220 ms | **只在我们自己的操作失败时**播一次 | 愣一下 → 冒汗 → 委屈掉泪；温和，不夸张 |
| 6 | `waiting` | 6 | 1010 ms | 闭眼（暂停 / 无痕 / 密码框）、小雨、夜里 | 闭眼打盹，头顶的“z”由小变大 |
| 7 | `running` | 6 | 820 ms | 专注结束（两轮） | 面朝前原地开心小跑 |
| 8 | `review` | 6 | 1030 ms | 专注中 | 认真看东西（拿放大镜或小本子左右看） |

**伦理约束（C-ETH）**：心情不好时**不会**播 `failed`，桌宠不评判用户；`failed` 只表示“我们自己出错了”，画成小小的委屈，
不要嚎啕大哭、不要倒地、不要出现文字或骷髅这类符号。求助入口出现时桌宠不表演，所以没有专门的“难过”动作，**不要擅自加**。

内置晴晴还要两张同尺寸的图：`body.png`（只有身体的白色蒙版，小组件按当前天气色 `--mf-w-*` 给身体上色）和
`lines.png`（身体以外的一切：描边、五官、腮红、道具、特效、影子）。导入的普通 Codex 桌宠只要 `spritesheet.png`。

## 二、生图规格（每张图都一样）

| 项 | 值 |
|---|---|
| 比例 | **2:3**（竖图） |
| 画布 | **1024 × 1536**（模型给别的尺寸也行，只要是 2:3，工具会缩放） |
| 网格 | **4 × 4**，每格 **256 × 384**，格子从左到右、从上到下编号 1–16 |
| 动作格 | **格 1–14**，每格一个独立动作帧（一张最多 14 个动作；用不满的格子留空） |
| 格 15 | **标准站姿**：每张都画同一个，和 `idle` 第 1 帧一样。工具用它统一比例和地面 |
| 格 16 | **色卡**：上、中、下三条横向色块，依次是身体色、描边色、主要点缀色（如腮红） |
| 背景 | 整张纯色 **#FF00FF**（品红），不要渐变、纹理、地面、阴影；角色身上不要用接近品红的颜色 |
| 格内位置 | 角色水平居中（x = 128），**脚底踩在 y = 320 的隐形地面线上**；起跳的帧才离开地面 |
| 站立高度 | 标准站姿从头顶到脚底约 **200 px**（格高的一半多一点），所有格子同一个比例，不要远近透视 |
| 边距 | 角色离格子左右边 ≥ 20 px、离上边 ≥ 24 px；任何部分不能越过格子边线，也不能碰到相邻格 |
| 禁止 | 网格线、边框、格子编号、文字、水印、签名、地面阴影（影子由工具统一加）、同一格里出现两只 |

切图工具按**精确四等分**切格子，不找边框。所以“每格内容不出界、不画格线”比什么都重要。

### 为什么是这个尺寸

- 4 × 4 的 2:3 画布，每格正好 2:3（256 × 384），给跳跃留出头顶空间；切出来按 0.6 倍缩进 192 × 208 的格子，
  站姿约 120 px 高，与现在的晴晴一样大。
- 每张画同一状态的连续帧，模型更容易保持同一张脸、同一个比例；格 15 的标准站姿让 5 张图之间也能对齐。

## 三、分张安排

动作的帧**不跨图**（同一个动作的所有帧在同一张图里画，前后帧才连得上）：

| 图 | 格 1–14 | 留空 | 说明 |
|---|---|---|---|
| `sheet-1.png` | 格 1–6 `idle` 第 1–6 帧；格 7–14 `running-right` 第 1–8 帧 | — | 先画这张，定下形象 |
| `sheet-2.png` | 格 1–8 `failed` 第 1–8 帧；格 9–14 `waiting` 第 1–6 帧 | — | |
| `sheet-3.png` | 格 1–6 `running` 第 1–6 帧；格 7–12 `review` 第 1–6 帧 | 13–14 | |
| `sheet-4.png` | 格 1–4 `waving` 第 1–4 帧；格 5–9 `jumping` 第 1–5 帧 | 10–14 | |
| `sheet-5.png`（可选） | 格 1–8 `running-left` 第 1–8 帧 | 9–14 | 形象左右不对称（比如只有一边有发夹）时才画；否则工具镜像 running-right |

每张图的格 15、16 都照第二节画。准确的格子 → 动作对照在 `layout.json`。

## 四、形象与画风规范

### 4.1 先定设定稿

正式出动作图之前，先单独出一张**设定稿**（正面站姿、侧面、背面、3–4 个表情），定好以后**每次生图都把设定稿作为参考图附上**，
并在提示词里写清楚固定的特征（见 prompts.md 的「角色设定」段）。5 张动作图要像同一只。

### 4.2 形象的通用要求

- 适合在 192 × 208 的小格子里认出来：轮廓清楚、细节少、五官大；不要细碎的头发丝、花纹、文字。
- 表情靠眼睛和嘴，温和为主（桌宠会长时间待在桌面上，夸张的表情容易烦）。
- 形象的具体设定（名字、比例、配色、固定特征）按 `references/prompts.md` 的「B 角色设定」模板单独写，**不写进本 skill**；
  内置晴晴的设定由维护者另行确定。

### 4.3 能随天气变色（内置晴晴必须满足）

小组件要把身体换成六种天气色（晴 #F6C344、一阵风 #9FD3C7、多云 #A99BD8、小雨 #7FA7C9、雷阵雨 #E8875B、夜 #9AA3B2），
所以身体必须能被一张蒙版干净地抠出来：

1. **身体只用一种平涂色**（就是色卡第一条），不要渐变、阴影、高光、纹理、描边内的明暗；
2. **描边统一一种深色**（色卡第二条，建议 #2B2A28），粗细一致，闭合；
3. 腮红、眼睛高光、道具、汗滴、“z”、星星等**用别的颜色**，它们会被放进 `lines.png`，不跟着变色；
4. 身体颜色不要在别处出现（比如道具不要用同一个黄色），否则道具也会被染色。

做不到平涂（比如想要有光影的画风）就用**不变色模式**：工具加 `--no-tint`，只出 `spritesheet.png`，小组件旁边挂小天气图标。
内置晴晴原则上必须能变色（DS-COLOR：看颜色知道心情天气），不变色要先写 ADR。

### 4.4 换装锚点（平时三种姿态）

装扮（草帽、围巾、耳机、眼镜……）只叠在内置晴晴的 `idle`、`waiting`、`review` 三个动作上，位置按“头部是一个圆”固定：
切好的 192 × 208 格子里，头部圆心约 **(96, 122)**、半径约 **54**（头顶 y≈68、眼睛 y≈117、下巴 y≈176）。
所以这三个动作里**头的位置和大小要稳定**，只能有呼吸那样的小起伏；工具会检查，偏差超过 12 px 报警。
形象要是头小身大、对不上这个圆，就要同步改 `App.vue` 的 `OUTFIT_K` 与装扮图形（另开任务）。

### 4.5 动作通用要求

- 循环动作（idle、running-right、waiting、running、review）的最后一帧要能**无缝接回第一帧**；
- 跑步类帧之间身体有上下起伏，但脚底接地的帧仍踩在地面线上；
- `jumping` 第 2–4 帧离地，最高点（第 3 帧）比地面线高约 80–100 px（格内像素）；
- 速度线、汗滴、“z”、星星、泪滴这些特效可以有，但都要在格子里，并用非身体色；
- 朝向：`running-right` 面朝**右**（画面右侧），其余动作面朝前或微侧。

## 五、提示词

用 `references/prompts.md`：一段**固定的总规范**（格式、背景、网格、禁止项）+ 一段**角色设定**（按模板为这只桌宠填一次，之后每张一样）+ 一段**这张图的格子清单**
（从 `references/actions.md` 抄对应动作的逐帧描述）。不同模型的写法差异也在那边。

## 六、出图到上线的流程

1. 出设定稿，和维护者确认形象（不满意就在这一步改，不要等动作图出完）。
2. 按第三节逐张出图，每张附设定稿参考图。每张出完先对照第七节自检，不合格就重画这张。
3. 把图放进一个文件夹，命名 `sheet-1.png` … `sheet-4.png`（有 `sheet-5.png` 也放进去），跑切图：

   ```bash
   python3 tools/pet_from_grid.py --in <图所在文件夹> --out /tmp/qingqing-new --preview
   # 不变色模式：加 --no-tint；导入用的普通桌宠：加 --id <编号> --name <名字>
   ```

   工具会：抠掉品红背景 → 按四等分切格 → 用格 15 统一比例与地面 → 缩到 192 × 208 → 排成 8 × 9 的精灵图 →
   按色卡把身体抠成 `body.png`、其余放 `lines.png` → 统一加脚下影子 → 写 `pet.json`；`--preview` 另出每个动作的 GIF 和一张总览图。
   有问题的帧会列在输出里（出界、空格、头部偏离锚点、身体色占比异常）。
4. 看 `preview/`：每个动作的 GIF 是否顺、5 张图之间大小颜色是否一致、换装锚点是否对。
5. 满意后把 `pet.json`、`spritesheet.png`、`body.png`、`lines.png` 覆盖到 `hub_templates/pets/qingqing/`，
   跑 `cd moodflow_hub && pnpm vitest run src/windows/widget` 与 `cargo test -p moodflow-hub`（`pets.rs` 里有用内置图做的导入测试），
   再在 Hub 里看小组件：六种天气色、拖动、扔、散步、换装。
6. 原始生成图（5 张 1024 × 1536）不进仓库，放到设计素材处；提交信息写明用的模型与日期，方便以后补帧时用同一个模型。

## 七、验收清单（每张图都要过）

- [ ] 尺寸 2:3；背景整张纯品红，没有地面、阴影、渐变
- [ ] 没有网格线、边框、编号、文字、水印
- [ ] 格 1–14 每格只有一只、动作与第三节对得上；该留空的格子是空的
- [ ] 每格内容都在格子里，离边 ≥ 20 px（上边 ≥ 24 px）
- [ ] 格 15 是标准站姿，格 16 是三条色块
- [ ] 所有格子同一比例；接地帧的脚底在同一条线上
- [ ] 与设定稿是同一只（脸、颜色、比例、配饰）
- [ ] 身体是单一平涂色、描边统一（变色模式）
- [ ] `failed` 温和；没有加项目不支持的动作

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 模型画了格线或编号 | 提示词里把禁止项放在最前面，并加“seamless background, no dividers”；仍有就换模型或在图上把线涂成品红再切 |
| 格子大小不齐、角色跨格 | 降低单张动作数（先只画 8 格、其余留空）再拼；或把“4 列 4 行等分”写成“每格 256×384 像素” |
| 每格角色大小不一 | 强调 “same scale in every cell, identical to cell 15”；工具按格 15 统一缩放，但格内差异需要重画 |
| 背景不纯、角色边上有品红光晕 | 工具会做容差抠图与去边；光晕重时提高 `--bg-tol`，或要求模型 “hard edge, no glow” |
| 身体有阴影，变色后很脏 | 回到 4.3 重画，或用 `--no-tint` |
| 前后帧不连贯 | 一次只画一个动作（两张图拼一个 sheet），并在提示词里写出前一帧的样子 |
