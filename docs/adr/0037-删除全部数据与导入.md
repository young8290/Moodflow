# 0037 删除全部数据与导入
- 状态：提议
- 日期：2026-10-15；提议人：D（代 E-01 / E-02 先行实现，设置页“隐私”分类要用）；待 E（隐私与数据，FR-DAT 负责人）、C（数据库）评审

## 背景
09 FR-DAT-04（删除全部数据，P0）、FR-DAT-05 第 3 条（撤回 ① 时可同时删除情绪数据）、FR-DAT-07（导入与恢复，P1）
是 E-01 / E-02 的后端，设置页“隐私与关于”（07 FR-SET-09）一直缺这几个入口。导出（FR-DAT-03）已由 E 实现
（`core/src/infra/store/export.rs`），删除和导入还没有人做，前端无法收尾。D 先按产品书实现，E 评审后可接手。

## 决策
1. **删除全部数据分两步，靠重启完成**（`core/src/infra/wipe.rs`）：运行中的 Hub 有十几个服务各自持有数据库连接，
   就地删文件在 Windows 上删不掉打开的文件，也可能被还没退出的写线程重新建出来。所以命令 `data_delete_all(include_secrets)`
   只在数据目录写一个标记 `wipe-pending.json` 并重启 Hub；下次启动时 `run()` 的第一步、任何东西打开数据库之前，
   按标记删掉文件、再删标记，然后照常启动——新库没有同意记录，自然进入首次引导。删不掉（被占用）时保留标记，下次启动重试。
2. **删除范围**：真实库与演示库（`xinqing.db`、`xinqing_demo.db`，连同 `-wal` / `-shm`）、数据库损坏时留下的
   `*.corrupt-*`、覆盖导入前的 `*.bak-*`；勾选时连 AI 密钥文件 `secrets.bin` 一起删。用户目录的模板覆盖（`templates/`）
   是配置不是个人数据，保留。Hub 目前不写日志文件和录制文件，FR-DAT-04 提到的这两类以后出现时加进 `targets`。
   输入法词库不在这个目录，不受影响。前端在调用前清掉 WebView 的 localStorage（小组件位置、首次引导交接等本机界面偏好）。
3. **确认方式**按 FR-DAT-04：输入“删除”二字后按钮才可点；10 秒内完成（删文件 + 重启，实际是一两秒）。
4. **撤回 ① 时删除情绪数据**：新命令 `data_delete_mood()`，在一个写事务里清空 `feedback`、`self_report`、`mood_state`、
   `window_features`、`baseline`，并把 `daily_summary` 的状态分布、主导状态、情绪倾向置空（同一行的输入时长、休息与饮水
   不是情绪数据，保留）；随后清空内存里的基线，重新进入冷启动。对话、日记、日程待办、周信等用户自己写的内容不动。
5. **导入只收自己的导出包**（`core/src/infra/store/import.rs`，命令 `data_import(path, mode, include_settings)`）：
   读 `manifest.json`，格式名不对、格式版本或数据库结构版本比当前新都拒绝；逐个文件核对 SHA-256，任何一个对不上整包拒绝；
   单个文件不超过 512 MB（读的时候也按上限截断，防解压炸弹）。三类拒绝各有一句说明（不是导出包 / 版本太新 / 不完整或被改过）。
6. **不导入**：同意记录（换了电脑必须重新同意，FR-DAT-07）、出网记录（是那台电脑的运行记录）；设置项由用户选择，
   选了也只收已登记的用户设置键（`settings::spec`），开发者选项 `dev.*` 和内部键不收。AI 密钥本来就不在包里。
   导出时给 AI 文字附加的 `ai_generated` 与“（内容由 AI 生成）”后缀在导入时去掉，库里存原文。
7. **合并**：内容完全相同（不算行号）的行视为同一条，跳过；其余作为新行插入、换新行号，引用它们的列
   （`mood_state.window_id`、`chat_message.session_id`、`feedback.target_id`）跟着换；以日期 / 键名为主键的表
   （每日汇总、基线、收集）已有的保留。同一个包导入两次，第二次全部跳过。
   **覆盖**：外壳先用 `VACUUM INTO` 把当前库备份到旁边的 `<库名>.bak-<时间>`，再在事务里清空可导入的表、按原行号写入；
   设置只替换导入的键。两种方式都在单个事务里，`defer_foreign_keys` 到提交时再查引用，任何一步失败整体回滚。
8. **导入后重启**：内存里的基线、状态快照、各服务缓存都来自旧数据，导入成功后界面提示“重新启动心晴后生效”，
   用户点“立即重新启动”（命令 `app_restart`）。设置窗口的能力文件加 `dialog:allow-open` 选备份文件。
   首次引导最后一页的“从备份恢复”入口另做。
