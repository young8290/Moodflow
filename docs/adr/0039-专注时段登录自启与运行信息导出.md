# 0039 专注时段、登录时后台启动与运行信息导出
- 状态：已接受（产品手册 V1.5 已同步，2026-10-15）
- 日期：2026-10-15；提议人：D（代 B-08 剩余与 A-10 / FR-OPS 的 Hub 一侧）；待 B（休息提醒）、A（安装包）、E（隐私）评审

## 背景
三个产品书要求一直没有 Hub 一侧的实现：06 FR-RST-09 的“专注时段”（P0，B 交接文档里写着“等 C 的自由文本设置类型”，
现在 `SettingItem::TimeRange` 已有）；11 FR-OPS-03 的“登录 Windows 时在后台启动 Moodflow”（P1，安装器已认领 Run 键值名
`MoodflowHub`，等 Hub 做设置）；11 FR-OPS-04 的“导出诊断信息”（P1）。

## 决策
1. **专注时段**用 10 第 6.2 节列出的键 `rest.focus_period`，形态同 `care.quiet_hours`：字符串列表，至多 1 项
   `"HH:MM-HH:MM"`，可跨午夜，空列表表示没设（出厂）。时段内休息提醒只保留深夜提醒，护眼、喝水、活动照常计时但不显示，
   出了时段按原规则提醒（多类同时到期仍是一次一个、其余顺延 5 分钟），不另做“合并成一次休息建议”——那是 P2 专注计时
   （FR-RST-10）结束时的行为。
2. **登录时后台启动**用 `tauri-plugin-autostart`，以系统里的启动项为准，**不另存设置键**：命令 `autostart_get` /
   `autostart_set` 直接读写 HKCU Run 键（值名 `MoodflowHub`，与安装器卸载时清理的一致；调试构建用 `MoodflowHubDev`，
   免得开发机上顶掉正式版），启动参数 `--background`。出厂关闭；设置“常规”的开关在读不到启动项时不显示；
   “恢复默认”会把它关掉。
3. **运行信息导出**（FR-OPS-04）：
   - 界面叫“导出运行信息”：“诊断”在禁用词表里（07 DS-COPY-03），界面文案不能用。
   - 包是 zip，固定 7 个文件：`README.txt`、`about.json`（Moodflow 与 Windows 版本、构建类型、是否演示模式）、
     `displays.json`（每块显示器的分辨率、位置与缩放）、`status.json`（是否连上输入法、离线、暂停、基线进度——**不含**
     当前情绪状态）、`ai.json`（两侧可用性、今日用量、各接口调用统计、最近 100 条出网记录：只有接口、模型、字段名、
     耗时、状态与 token 数）、`templates.txt`（用户覆盖了哪些模板文件，只列文件名）、`hub-log.txt`（最近的运行日志）。
     **不含**数据库、密钥、AI 服务地址、设置值和任何用户写的文字。导出前界面先列出这 7 个文件及各自内容，用户确认后
     再选保存位置。
   - Hub 一直只写标准错误、没有日志文件（ADR 0037 第 2 条）。新增 `runlog`：原来的 `eprintln!` 全部改走 `hlog!`，
     照旧写标准错误，另在内存里留最近 500 行，导出时放进 `hub-log.txt`；不落盘，退出即清空。这些行按 NFR-LOG
     本来就只有连接状态、计数、错误原因。

## 影响
- 06 FR-RST-09 写明专注时段的形态与“期间照常计时、过后照常提醒”；10 第 5.1 节补命令 `autostart_get`、
  `autostart_set`、`diagnostics_preview`、`diagnostics_export`；11 FR-OPS-04 改为“导出运行信息”并列出包内文件，
  说明日志只在内存里保留最近 500 行。
- 没有新迁移、新事件；新增设置键 `rest.focus_period`。

## 验证
`domain/rest.rs` 测试：专注时段内护眼不提醒、打到时段之后立即提醒，深夜提醒在时段内照常。设置页测试：专注时段的设定、
校验、跨午夜显示与取消；登录自启的读取、开关、恢复默认关闭、读不到时隐藏。`diagnostics.rs` 测试：包内文件与预告清单一致、
不含情绪状态、出网记录截到 100 条、zip 可读；`runlog.rs` 测试：只留最近 500 行。界面测试：先列文件再导出、取消对话框不导出、
失败说明原因、文案不含“诊断”。
