# 0055 换 AI 服务地址须重新填写密钥
- 状态：已接受（用户要求吸收 XSIME 的长处，2026-10-17）
- 日期：2026-10-17；提议人：用户（经 XSIME 吸收计划 §3.1）；待 E（隐私、安全）事后评审；修订 ADR 0012 第 3 条

## 背景
ADR 0012 第 3 条规定 `secrets_set` 里「没填的密钥沿用旧值」，界面提示「留空表示不改」。这让用户只改模型或地址时不必重新输入密钥，
但也意味着：只改地址、不改密钥时，旧密钥会被发给**新的**地址。用户填错一个中转地址，或照着来路不明的教程填了地址，
密钥就出网了，用户还以为「我没动密钥」。

XSIME 的做法是修改 API 地址后必须重新填写密钥，旧密钥不会转发到新地址。

## 决策
1. **只在服务主机不变时沿用旧密钥。** 「主机不变」= 协议、主机名（不区分大小写）、端口（缺省按协议补齐）都相同；路径、模型可以改。
   例：`https://llm.example/v1` → `https://llm.example/v2` 沿用；→ `https://other.example/v1`、`http://llm.example/v1`、
   `https://llm.example:8443/v1` 都算换了主机。
2. **换了主机而密钥留空时拒绝保存**，返回 `error.ai_key_required`（`ui_copy.toml`：「换了服务地址，请重新填写密钥再保存。旧密钥不会发给新地址。」），
   不静默清空密钥，也不静默沿用。
3. 地址解析不出主机时按「换了主机」处理（宁可多问一次密钥）。
4. 其余规则照 ADR 0012：某一侧整个为 `null` 表示清除这一侧；密钥只进不出；release 只收 `https://`（回环地址除外）。

## 实现
- `moodflow_hub/gateway/src/secrets.rs`：`AiSecrets::merged_onto` 改为返回 `Result`，新增 `SecretsError::KeyRequired`，
  主机比较在 `same_origin`。
- `moodflow_hub/src-tauri/src/gateway.rs`：`Ai::save` 把错误交回命令层；`commands/ai.rs` 映射为 `ai.key_required` / `error.ai_key_required`。
- 测试：同主机改路径沿用、新主机留空拒绝、新主机带新密钥照常保存、主机比较的边界（大小写、默认端口、子域名伪装、userinfo、IPv6）。

## 备选方案与取舍
- 换主机时静默清空密钥：用户保存成功却发现 AI 不能用，排查成本高。没有采用。
- 任何地址变化（含路径）都要求重填：同一服务换 API 版本路径很常见，要求重填只增加摩擦、不增加安全。没有采用。

## 影响
- 产品书 08 FR-AIG-06、10 第 5.1 节 `secrets_set`、18 TC-AIG-09 改为「主机不变才沿用」，并在 00 第 5 节记录。
- 设置页（D）：密钥框占位提示改为「留空表示不改（换了服务地址需要重新填写）」；收到 `error.ai_key_required` 时把焦点放到密钥框。
